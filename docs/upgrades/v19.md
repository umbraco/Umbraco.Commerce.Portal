# Upgrade to Umbraco 19

From Umbraco CMS `[18.0.0, 18.999.999)` / Umbraco Commerce `[18.0.0, 18.999.999)` to CMS `19.0.0-beta1` (tag `release-19.0.0-beta1`) / Commerce `19.0.0-beta.1`.
Branch `topic/19.x/cms-19-upgrade` → PR into `release/19.0.0`, cut from `main` (`2646713`).

**Targets CMS release:** `release-19.0.0-beta1`. The package's own version is `19.0.0-beta.1`.

The full CMS breaking-change inventory for 19.0.0-beta1 was done for Commerce Core (Core repo, `docs/upgrades/v19.md`), and Checkout (the closest sibling: installer, backoffice dashboard, Razor storefront) applied it to an add-on. This file lists what hits Portal, checked against those lists, the 27 `category/breaking` CMS PRs in 19.0.0-beta1, a v18 and a v19 build (CS0618), and `@typescript-eslint/no-deprecated` on the v18 and v19 typings.

## Customer entities and address book

Branch `v19/topic/customer-entities`, stacked on `topic/19.x/cms-19-upgrade` (#26). Moves the member profile and billing details onto Commerce Core's `Customer` / `CustomerAddress` and replaces the single billing form with an address book.

### What changed

- New `PortalCustomerService` (scoped): the signed-in member's customer for the current store (the page's store, `GetStore()`). Looks it up by member key, then by email (and links it), and creates one when neither exists.
- My Account edits first name, last name, email and phone number on the customer, and keeps the member's name and email in step (the username still follows the email).
- Address book: lists the customer's billing and shipping addresses (including those Core saves from finalized orders), with add, edit, delete and set default. Country is a select of the store's countries; the state / province select appears only for countries with regions.
- Registration creates or links the customer with the entered first name, last name and email.
- Order History lists the member's finalized orders: orders linked to their customer, plus orders assigned to the member key or placed with their email (orders from before the customer record existed), without duplicates, newest first.
- Account actions now act on the signed-in member: the account surface controller requires a signed-in member, the forms no longer post member ids, address edit/delete/default check the address belongs to the signed-in customer, change password works on the signed-in member, and Order Details only shows the signed-in member's own finalized orders in the store.

### Decisions

- 31-10-2026: First-visit copy of the old member properties is tracked with the customer property `ucpLegacyProfileImported`, not with "no customer linked yet": Core already links customers to members by email (`LinkCustomersToMemberOnMemberSaved`, `SyncCustomerOnOrderFinalized`), so most existing members already have a linked customer before Portal sees them.
- 31-10-2026: The copy fills the customer's first/last name only when the customer has none (a customer created from orders keeps its names). The old address becomes a billing address, default only when the customer has no default billing address, and is skipped when the customer already has the same address. Country: the old property's country id, or a country code (what the old billing form posted). State: matched to a region of that country by name or code (also ignoring a `US-` style prefix); left out when nothing matches.
- 31-10-2026: When a member's key-linked customer has a different email than the member and no customer of the store has the member's email, the customer's email is updated to the member's. When another customer has the member's email, that customer is used and linked.
- 31-10-2026: An email change is refused ("already in use") when another member, or another customer of the store, has that email. Core enforces unique customer emails per store, so merging customers is left out.
- 31-10-2026: The first address of a kind becomes its default. Editing can't unset a default (that would leave the kind without one); defaults move with "Set as default". An edited address keeps its kind.
- 31-10-2026: Addresses with a country outside the store, or a region outside the chosen country, are refused.
- 31-10-2026: Order Details requires the order to be finalized and in the page's store, besides belonging to the member.
- 31-10-2026: Public API kept with `[Obsolete]` proxies (removal in v21.0.0) rather than removed: the old controller constructors, `UpdateBillingInformation` (now saves the default billing address), `BillingInformationModel`, `AccountModel.Id`, `ChangePasswordModel.MemberKey`, `PortalMemberService.Get`/`GetBillingInformation`, `PortalMemberExtensions.ToAccountModel`/`ToBillingInformationModel`. The tests of the two obsolete mappers were replaced by tests of the new legacy-profile reader, so the test project builds without obsolete-usage warnings.
- 31-10-2026: The `ucpLegacyProfileImported` marker is saved after the old address is copied, so a failed copy is retried on the next visit (reviewer).
- 31-10-2026: Region select is a few lines of inline script in the My Account view (same approach as the toast partial); delete asks for confirmation through a `data-confirm` attribute.

### Breaking changes for consumers

- **Behaviour change: the `ucpMember` profile properties are no longer written.** Portal reads profile and addresses from the Commerce customer. The properties and the member type stay, and their values are copied onto the customer once. Code or templates reading `ucpMemberFirstName`, `ucpMemberLastName`, `ucpMemberCountry`, `ucpMemberStreet`, `ucpMemberCity`, `ucpMemberState` or `ucpZipCode` should read the customer (`PortalCustomerService`, or Core's `ICustomerService`) instead.
- My Account forms changed: the account form has a `Telephone` field and no hidden `accountModel.Id`; the billing form is replaced by the address book (`SaveAddress`, `SetDefaultAddress`, `DeleteAddress`, model `AddressBookAddressModel`); the change password form has no hidden `MemberKey`. Overridden copies of `UmbracoCommercePortalMyAccountPage.cshtml` and `UmbracoCommercePortalOrderHistoryPage.cshtml` should be updated; the old posts keep working through the obsolete members.
- Posted `AccountModel.Id` and `ChangePasswordModel.MemberKey` are ignored.
- `UmbracoCommercePortalAccountSurfaceController` requires a signed-in member (`[UmbracoMemberAuthorize]`).
- Order History is sorted newest first.
- New constructor dependencies (`PortalCustomerService`) on `UmbracoCommercePortalAccountSurfaceController`, `UmbracoCommercePortalSurfaceController` and `UcpPortalOrderDetailsPageController`; the old constructors are obsolete.

### Follow-ups

- The billing information save 500 (Follow-ups above) is gone: the billing form is replaced by the address book, and the obsolete `UpdateBillingInformation` saves the default billing address.
- Core overwrites a customer's first/last name with the order's on every finalized order (`SyncCustomerFromOrderAsync`), so names edited in My Account change after the next order. Raise with Core if customers should keep their own names.
- Core can link more than one customer of a store to the same member key (e.g. after a member's email changes in the backoffice, `LinkCustomersToMemberOnMemberSaved` links the customer with the new email too), and `GetCustomerByMemberKeyAsync` returns the first. Portal prefers the customer whose email matches the member's.
- Customer addresses Core saves from orders are never default, so a customer with only order addresses has no default until they pick one.
- Two first visits of the same member at the same moment can both create a customer: Portal retries once on Core's unique-email validation, but Core has no database unique index on customer email per store. Raise with Core if this matters.
- Saving a customer in the backoffice may drop custom properties it doesn't show, including `ucpLegacyProfileImported`; the copy would then run again (it skips addresses the customer already has, but would re-add one the member deleted). Not checked.
- Still open from above: confirmation email link encoding, Order Details showing the billing country for the shipping address, unpublished install, the `**/*.cshtml` content glob picking up `bin/` copies (seen again in this work: stale `bin` view copies produced obsolete-usage warnings until `bin` was cleared), `GetPagedOfType(..., null)`, the bare `[Authorize]`.
- Pre-existing: `ChangePassword` showed identity error objects' type names instead of their descriptions; fixed in passing.
